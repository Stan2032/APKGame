## [0.16.6] — 2026-08-07
- **Re-measured generation, and both standing performance claims turned out to be inverted.**
  - PERFORMANCE.md said the worst case was **difficulty 0** at 100–200ms. It is **difficulty 11 at ~684ms** (d0 101, d3 102, d6 77, d9 164). The old reasoning was sound when written — easy levels need a *rare* high-hit-rate layout, so the generator burns attempts — and has simply been overtaken: the acceptance band narrows as difficulty climbs, so hard levels burn the attempts now.
  - TODO called duel generation "the slowest path in the game" at ~330ms. Duels measure **343ms** — half of difficulty 11. Anyone who took that item at face value would have optimised the wrong path.
- **The hot path was measured, not guessed — and the guess was wrong.** My first hypothesis was the three objective proofs, since `withObjective` runs all of Capture, Courier and Thread to pick one. Comparing CAMPAIGN against DAILY on identical seeds isolates them (only campaign assigns objectives, D-27): at difficulty 11 the **layout/solver loop is ~83%** of the cost and all three proofs together are ~17%; at d9 it is ~70/30. The proofs are not the problem. This is the PERFORMANCE.md discipline working exactly as intended — the guess would have sent an optimisation at the smaller of the two costs.
- **Deliberately measured rather than optimised, and the reason is a constraint worth recording**: anything that changes what a seed *generates* is a protocol break, because a campaign replay code regenerates the spec on the receiving device. So a faster search order or a different acceptance rule is not available — only changes that provably preserve output. Making a subtle behavioural change to the generator while unable to push or run CI (see below) would have been the wrong order of operations.
- ⚠️ **Push blocked, work preserved.** This container's git credential proxy stopped authenticating mid-session: `push` *and* `fetch` both fail with `could not read Username`, and a dummy-credential probe reached GitHub and came back with a real "Invalid username or token" — so the proxy forwards traffic but no longer injects credentials. The GitHub API path kept working throughout, which is how CI was confirmed green on `ceeb7cc`. Commits from 0.16.5 onward are held locally and exported as patches so they survive container loss.

## [0.16.4] — 2026-08-07
- **The seven SFX have been heard.** They had gone un-auditioned since 0.2.0 — and it turns out they never needed a tool, a task or a device: they are already `.wav` files sitting in `res/raw/`, listenable by anyone who opens the repo. My own TODO item proposed building a dump task for them, which was the overcomplicated answer to a problem that did not exist. The gap lasted fourteen versions because everyone, me included, assumed a device was required.
- **`tools/audio_report.py`** measures every cue — duration, peak, RMS, clipping, trailing silence — and then does the thing separate files cannot: **lays real SFX over a real pad at the exact volumes `GameScreen` passes to `SoundPool`**. That mix is the actual answer to AUDIO.md §7's open question about whether the pad sits right under the effects; two files played one after another cannot answer it.
- **Measured, and mostly clean**: no clipping anywhere, no trailing silence, all seven at 22.05 kHz — the same rate as the pad, so nothing resamples. The pad's −10.5 dBFS sits 5 dB under the cues' −5.2 to −6.1, which was chosen for the pad in 0.14.0 and is now confirmed against the SFX that already existed. The combined mix peaks at −1.8 dBFS with headroom to spare.
- **One real finding: `sfx_brake` is 5 dB below every other cue** — level with the *pad*, not with its siblings. It is also the cue confirming the most timing-critical input in the game: the Capture insertion burn, where *when* you fire the brake is the entire skill (D-26). A confirmation you might not hear, for the one input whose timing decides the objective, is the wrong thing to have quiet. Deliberately **not** changed — whether it is actually inaudible is an ear question, and adjusting a shipped asset on the strength of a number alone is what this repo keeps warning against.
- Recorded a sequencing constraint rather than tripping over it: **multi-pulsar polyrhythm needs a protocol bump** (a per-body period changes what a seed generates), and there is already an open protocol question from 0.16.3 (should trails travel?). Two separate bumps would invalidate every code in the wild twice; the second is free if it rides the first. So polyrhythm waits for that decision instead of forcing a second one.

## [0.16.2] — 2026-08-07
- **The stars land.** A campaign clear used to print `★★☆` as text — a result stated, nothing celebrated, on the one screen whose entire job is to say *well done*. It is also a listed store screenshot, and a row of glyphs sells nothing. Now each earned star arrives with an overshoot and a ring of rays, **staggered** so three stars read as three arrivals rather than one; the third one landing is the beat a player waits for. Unearned stars are drawn hollow from the start and never animate — the gap between what you got and what was available should be visible, not performed.
- Drawn as a path rather than typed, because `★` is a font's opinion: it differs across devices and cannot be made to burst.
- **And the accessibility hole that finding it exposed.** Android lets a user zero the animator duration scale, and accessibility guidance tells people with vestibular disorders or motion sensitivity to do exactly that. The system then stops running *animators* — but it cannot stop a game that draws its own motion frame by frame, and ours does. **The camera shake has ignored that setting since it shipped in 0.13.1**: a player who had turned animations off system-wide still got the board thrown around on every kill, with no in-app switch to stop it. Nothing failed, because nothing ever fails when an accessibility setting is quietly ignored.
- `ui/Motion.kt` now asks, and both the shake and the new flourish obey (D-35). **The line is decoration versus information**: the projectile still flies, the trail still draws, the preview still updates, and where a flourish would otherwise *reveal* something — the stars — the finished state is drawn at once rather than not at all. Reduced motion means do not decorate with movement; it never means hide what is happening.
- A new extension rule follows from it: any future hand-drawn animation must gate on `animationsEnabled()`, and any that conveys state must degrade to its end state rather than to nothing.
- `StarBurstTest` (2) checks the two things that break silently: it composes at every star count (an off-by-one between earned and unearned would crash the summary — the screen that ends *every* match), and it still **speaks**. The stars used to be text, which TalkBack read for free; a Canvas has no text, so the semantics are declared by hand. A screen that looks better while being less usable for someone who cannot see it is the regression worth testing for.
- Tests: 190 (121 `:core` + 69 `:app`), 2 new.

## [0.16.0] — 2026-08-06
- **Expedition is playable.** The junction screen, the run's home between systems, and a Home entry to reach it. VISION Stage D is complete.
- **The screen answers one question — which way, and can I afford it?** So every number a route card shows is in the same unit as the gauge above it: travel is stated *before* the leg is taken, and each card gives the fuel a clear returns at one star and at three. A run mode where the price appears after committing feels arbitrary rather than tense, and tension is the entire product here.
- **The fuel gauge is drawn relative to the tank you started with, not to a maximum**, because there isn't one — fuel can and should exceed the starting tank on a good run, and a bar pinned at "full" would hide exactly the stretch a player most wants to see. Below a couple of legs' worth it turns amber and says so in words.
- Difficulty shows as pips, not the generator's 0–11. Nobody reads 0–11; what a player needs at a junction is "harder than the last one" at a glance.
- **A leg exits to the junction, never to the star map**, and launches with sector/level −1 so an Expedition clear can never hand out campaign sector unlocks for systems the player never found on the grid. Held by a test, because the two modes now share a generator and it would be an easy thing to break silently.
- **The run banks the moment it ends, not when the player taps through the summary** — the screen showing a payout must not also be the thing deciding whether it happened. Keyed on the run itself, so a recomposition cannot pay twice and an abandoned run cannot pay at all.
- **No mid-run save, deliberately** (D-9's reasoning applied to D-34): a run is a sitting. Persisting one would mean persisting the generated leg, the fuel and the match inside it — and would invite quitting out of a system that went badly in order to reroll it, which is precisely the pressure the mode exists to create.
- The Home glyph is a path that forks — one line in, three out. The whole decision a run keeps asking, drawn once, rather than a second copy of the campaign's orbit mark.
- Tests: 184 (121 `:core` + 63 `:app`), 5 new — including that an Uncharted card names its condition, since a condition the card does not mention would make Uncharted a third difficulty label.

## [0.15.1] — 2026-08-06
- **CI release signing, wired and self-activating.** It was the last agent-doable item on the launch path, and it was marked "blocked on the keystore existing" — which was true of *using* it and not of *building* it. Add four repository secrets and the next run signs; there is no flag to remember and no workflow edit to make later, which is the failure this shape is designed against.
- **The real hazard here is not a broken build, it is a plausible one.** `app/build.gradle.kts` deliberately falls back to the debug key so release builds stay installable for testing — which means a debug-signed `.aab` is byte-for-byte as convincing as a real one in a downloads folder, right up until Play refuses it and you spend an hour doubting the build rather than the key. Three defences, all cheap:
  - `verify_release_apk.py` now prints **`signed by:`** on every run, naming the certificate, and says plainly that a debug key is "installable for testing, rejected by Play".
  - A new `--require-upload-key` flag turns that into a failure. CI passes it **only when it actually signed**, so an unsigned repo stays green while a signed one can never hand back a debug-key artifact that merely looks upload-ready.
  - The bundle artifact is named `gravity-gambit-release-aab-DEBUGKEY-DO-NOT-UPLOAD` when unsigned. The *name* carries the warning, because that is the one piece of metadata that survives being downloaded.
- Keystore handling: decoded into `RUNNER_TEMP` rather than the workspace, so it cannot be swept into an artifact upload; `chmod 600`; shredded in a step that runs even when the build fails.
- LAUNCH_GUIDE Phase 3 gains the secret-setup step *at the point the keystore is already open* — the two minutes are only cheap there — with the macOS `base64` caveat spelled out, since `-w0` does not exist there and a keystore with embedded newlines decodes to garbage.

## [0.15.0] — 2026-08-06
- **Expedition — the run mode. Engine and economy; the UI is the next unit.** VISION Stage D, and the first mode where you can *lose something*. The campaign is a list: you can put it down after any level and lose nothing, which is what makes it a good teacher and a poor reason to open the app again.
- **Additive, exactly as D-32b directed — and the shape follows from that.** A leg is an ordinary `GameMode.CAMPAIGN` match, so Expedition is the state carried *between* existing matches. Nothing here touches `MatchEngine`, `ShareCodec` or the determinism contract: **a whole new mode cost the replay protocol nothing, and needed no version bump.** It also leaves D-27 ("objectives are campaign-only") true by construction — an Expedition leg *is* a campaign match, so it is entitled to Capture, Courier and Thread without a special case.
- **The test rewrote the design, and this is the part worth reading.** The first economy escalated the cost of a *shot*. `runsAlwaysEnd` — which plays the best player the rules permit — failed immediately: a per-shot cost cannot clock a player who fires one shot, so the perfect run reached the leg cap **with a full tank**. Expedition was an idle game with extra steps and would have shipped that way on a plausible-looking curve.
  - The fix is structural rather than a retune: **travel to the next system costs fuel, and travel cost rises without bound** while refunds are bounded above by a `MAX_REFUND` *derived from the route and mutator tables rather than typed in*. Past a computed `BLEED_DEPTH`, every leg is a net loss no matter how perfectly it is played. Runs end by arithmetic, not by hoping the difficulty curve outruns the player.
  - A second test re-derives `MAX_REFUND` by sweeping every route × mutator × star combination, so the termination proof cannot rot when someone adds a richer route.
- **One resource, not three.** Hull and cargo would each need their own rules, readout and failure state to earn their place, and nobody holds three trend lines in their head between shots. Fuel leaves by travel and by shooting, and returns by clearing.
- **A wreck advances the run rather than ending it.** Ending on one bad system would make the opening minute the whole game — and would punish precisely the player who took the hard route, which is the choice the mode exists to encourage. The tank is what ends you, not a single failure.
- **Three routes, and the risk genuinely pays**: the quiet way (easier, less fuel), the deep way (harder, more fuel), and Uncharted (unchanged odds, plus a condition). A junction is deterministic in seed and depth, so leaving and returning cannot reroll it into something better, and all three offers are *different systems* rather than one board with three difficulty labels.
- **Mutators are run rules, never generator requests.** "Binary star ahead" would have to ask the generator for a layout it may not be able to produce in band, and the fallback would leave the run claiming a condition that never applied — the exact failure D-24 and D-27 exist to prevent. Field-shaping mutators are deferred until the generator can *prove* one took.
- **Blind ships at last, as the *Dark run* mutator.** D-23 cut it from Gambits because nothing in a `TurnInput` records whether the sender looked at their preview, so a peer would have to take the claim on trust. That objection is entirely about verification *by a stranger* — and a solo run sends nothing to anyone. The idea was always good; it was the scoring that was unverifiable, and a run is the one place it never needs to be.
- **The meta-currency is stardust**, the currency the game already has. VISION asked for a new one; minting an unspendable token before the thing it buys exists is a number that goes up and means nothing. The unlock ladder and its currency arrive together in a later unit or not at all.
- Run length is **modelled, not measured** — expert 27 legs, steady 22, rough 15 under stated archetypes — and labelled as such, the same standing as the season tier curve (D-30). Whether that is a sitting or a chore is a playtest question, and it is one constant.
- **VISION §4 was still arguing with §3.6.** It listed "sector/level checklist campaign → becomes Expedition" two versions after D-32b reversed exactly that. A doc that contradicts itself is worse than one that is merely out of date, because both halves look authoritative. Corrected, with the original complaint kept and answered rather than deleted.
- Tests: 179 (121 `:core` + 58 `:app`), 17 new.

## [0.14.0] — 2026-08-06
- **The game has music.** It had none at all — the single largest presentation hole, and the one that could not be filled by writing some, because every level here comes from a seed and there is no finite set of places to score. One shared background loop would have said nothing about where you are.
- **So the pad is generated from the board.** Each body that matters gets a voice: pitch from its mass (heavier sits lower), phase from its position, tremolo from its kind, and the whole chord drawn from an interval set chosen by the **objective** — Breach is bare fifths, Capture is minor and unresolved, Courier refuses to settle, Thread is the only one that sounds resolved. A system with one huge star and two pebbles does not sound like three even worlds, because it is not.
- **A pulsar's voice swells at the pulsar's real gravity period**, and that is the point of the whole feature: the field can now be learned **by ear** before it is a rule. `PULSAR_PERIOD × DT` is exactly 3.5 seconds, so the loop is **7 seconds** — the smallest whole number of seconds holding a whole number of pulsar cycles. Because the loop is an integer multiple of the period, looping forever never drifts out of lock, and the app seeks to sample zero when you fire so the swell you hear is the pull the shot is flying through. This is VISION Stage E's sonification half, taken early (D-33).
  - The claim is scoped honestly in code and docs: the tremolo runs at the pulsar's rate always, but it only reports *phase* because playback restarts on fire. Systems with no pulsar skip the seek entirely — there is nothing to learn from locking a system with no pulse.
  - A test fails loudly if a future retune of `PULSAR_PERIOD` breaks the divisibility, because the game would otherwise go on claiming the pad tracks the pull.
- **The loop is seamless by construction, not by tuning.** Periodicity is stored as *integer cycles per loop* rather than hertz — frequency is the derived quantity — so a clicking seam is not a bug that can be introduced, and the same holds for every tremolo. Verified the way an ear would check it: the step from the last sample to the first must be no larger than the largest step anywhere inside the loop.
- **And it is exactly in tune at the same time**, which normally fights seamlessness — snapping frequencies to a loop grid detunes the intervals, and pure intervals put the seam back. They stop fighting if the root comes from a divisible grid: every root is a multiple of 80 cycles and every ratio denominator divides 80, so exact just intonation and an exact seam hold together with **no rounding anywhere**. Detuning is then deliberate — one cycle per loop is 1/7 Hz, so two voices beat once per loop and the beat loops seamlessly too. Without it, a sum of pure tones is dead air.
- **Zero APK bytes and zero CPU while playing.** Nothing is shipped; the loop is computed on a background thread in ~40ms (desktop) once per system, then handed to the audio HAL with `MODE_STATIC` hardware loop points, so an hour of drone costs no application CPU. That option only exists *because* the seam is exact — a seam would have forced a crossfading streamer and a thread to run it for the whole match. The mathematics pays for itself in battery.
- **`./gradlew :core:ambienceWav` writes sample pads to .wav.** Sound is the one generated thing here that measurement cannot sign off: a loop can pass every assertion and still be unpleasant to sit inside for ten minutes. The seven SFX have been un-auditioned since 0.2.0 purely because listening seemed to need a device. It does not need a device — it needs a file.
- **Ambience is its own setting**, separate from sound effects, because wanting a hit to land audibly and wanting a drone underneath it are different wants; collapsing them forces anyone who objects only to the second into silence.
- Deliberately **outside the determinism contract**: never hashed, never simulated against, never on the wire. Two devices replaying a duel hear the same pad because they generate the same system, but nothing checks that and nothing should — the day verification depends on an audio buffer is the day audio tuning becomes a protocol break. No protocol bump; every existing challenge code still verifies.
- Docs: new **docs/AUDIO.md** (both sound systems, the tuning mathematics, the honest scope of the pulsar claim, and the open questions for the first playtest); D-33; ARCHITECTURE, PERFORMANCE, VISION §3.4/Stage E and the release QA checklist updated.
- Two stale entries found in the ARCHITECTURE file map while adding the new ones and fixed: `BodyKind` was still listed as STAR/PLANET/REPULSOR (comets and pulsars have existed since 0.4.0) and the IAP count still read "3 INAPP" after `season_pass` made it four.
- Tests: 162 (104 `:core` + 58 `:app`), 10 new.
