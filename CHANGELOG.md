## [Unreleased]
- `pending` — `docs/LAUNCH_GUIDE.md`: complete step-by-step path from empty Play account to revenue — signup, **payments profile + bank verification + tax** (started early because the micro-deposit takes 3-5 days and no money moves until it clears), keystore, upload, all App-content forms with the exact answers for this app, the 12-testers-for-14-days gauntlet, creating and **activating** all five IAP products, license testing, staged rollout, and post-launch. Verified against Google's live docs with links; flags the three multi-day waits that actually set the launch date, and the Data-Safety trap of claiming "no internet permission".
- `pending` — Tests: the match screen — the game itself — had never been rendered by any test, and neither had the shop. `GameScreenTest` (5) now covers campaign/daily HUDs, the first-launch coaching hint showing only for fresh profiles, and the corrupt-code refusal screen; it required solving a real testing problem (continuous ambient animation means the composition never idles, so the default clock hangs — documented pattern: manual clock + polling pump). `ShopScreenTest` (4) proves the shop degrades gracefully with billing unconnected and ads off: earnable content renders, purchase/ad sections self-hide instead of showing stubs. App-module tests 21 → 30; every screen in the app is now rendered by at least one test.
- `pending` — **Correction (user-facing):** the shipped APK does carry `INTERNET` + `ACCESS_NETWORK_STATE`, contributed by `com.google.android.datatransport` transitively via Play Billing — the previous "no internet permission" claim had been asserted from our source manifest and never verified against the built artifact. Our code still performs zero networking and the game remains airplane-mode-complete, so every claim was rewritten to describe *behavior* rather than the permission list (privacy policy, in-app Settings text, store copy, README, checklist, MULTIPLAYER, DESIGN, D-3). Not stripped via `tools:node="remove"` — breaking purchases to win a marketing line is a bad trade; revisit with a device. New `tools/verify_release_apk.py` audits the release APK on every CI run: permissions must match an explicit allowlist, all five kotlinx-serialization serializers must survive R8 (a stripped serializer would wipe saves at runtime, invisible to unminified unit tests), and the APK must stay under a size budget.
- `pending` — Share text rewritten: a duel code is often the recipient's first contact with the game, and it previously arrived as "Your move. ⚔️ GG1.xK9…" — meaningless to someone without the app. Messages now say what the game is and exactly where to paste, via a new `ShareMessages` with a `STORE_URL` hook that turns every shared code into an install link at launch (tests forbid placeholder links before then, and verify the embedded code still survives the decoder's substring scan).
- `pending` — `GeneratorSweepTest`: ~50 generated systems across four sectors, extreme difficulties (0-20), a month of dailies (including relocation targets) and duels, all asserted solvable, in-bounds, and station-clear — a single unwinnable level in the wild is a one-star review. Daily numbering pinned to its launch date (verified 20666 = 2026-08-01).
- `pending` — Accessibility: the app had **zero** content descriptions. The match Canvas now carries a live spoken description (system name, aim angle/power, HP or shot count, replay state); decorative canvases are excluded from the accessibility tree; campaign level cells expose "Level 3, 2 of 3 stars" instead of unreadable star glyphs. Fixed-height controls (FIRE, RETRO BURN, level cells) became `heightIn(min=)` and the projectile chips became a `FlowRow` — both clipped at large system font sizes. New `AccessibilityTest` renders screens at 1.8-2.0x font scale to guard it; rules added to AI_LOOK_AVOIDANCE.md. App-module tests: 13 → 17.
- `pending` — Tests: Robolectric brings the UI under test on the JVM — no screen can now ship having never been rendered. `AppSmokeTest` (7) covers screen composition, navigation routing, daily seed wiring, and garbage-code rejection; `MatchControllerTest` (6) covers the phase machine, the **full code-duel round trip** (emit → import → verify → replay → both devices agree on HP and hash), forged-code refusal, hot-seat handoff, aim clamping, and feedback-code verifiability. Both wired into CI ahead of artifact builds, alongside lint.
- `pending` — Perf: solver early-exit (abandons candidates provably outside the difficulty band mid-scan; duels skip the mirror solve unless side one qualifies) — roughly halves worst-case level generation, which is difficulty 0, i.e. a new player's very first level. New `GenerationPerfTest` guardrails with printed timings; aim preview measured at 0.065ms/call (no action needed, documented so nobody re-optimizes it). Art: `AmbientBackdrop` — drifting starfield, nebula wash and a slow comet behind every menu screen at a 30fps cap, with translucent panels so the sky shows through; `OrbitRule` divider available. Findings recorded in docs/PERFORMANCE.md.
